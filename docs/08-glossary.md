# 08 · Glossary

## Three things called "DEX"

| Name | What it is | Used here for |
| --- | --- | --- |
| **Dex** (dexidp.io) | Open-source federated OpenID Connect provider with connectors to LDAP, SAML, GitHub, Microsoft and others. CNCF sandbox project | Single sign-on and group-based access across platform tools (Phase 4) |
| **DX** (getdx.com) | Commercial developer-intelligence product and the DX Core 4 framework. Part of Atlassian since the acquisition announced in September 2025 | An option for measuring productivity and AI impact (Phase 7) |
| **DevEx / DX** (developer experience) | The discipline, and the research framework with three dimensions: feedback loops, cognitive load, flow state | What the platform exists to improve |

## Terms

| Term | Meaning |
| --- | --- |
| ADR | Architecture Decision Record. A short, dated note of a decision and its reasons |
| Backstage | Open-source framework for developer portals, created at Spotify, now a CNCF project |
| Buildpack | Tool that turns source code into a runnable image without a Dockerfile. Popularised by Heroku; standardised as Cloud Native Buildpacks |
| Catalog | Inventory of software, owners, APIs and resources in the portal |
| Clean core | Keeping an ERP as standard as possible and placing extensions outside it, connected through APIs |
| CNCF | Cloud Native Computing Foundation |
| CNOE | Cloud Native Operational Excellence. Open project with a reference IDP and the `idpbuilder` tool |
| CNPA / CNPE | CNCF platform engineering certifications, associate and professional level |
| Cognitive load | The mental effort a developer spends on things other than the problem they are solving |
| Connector | In Dex, the adapter to one upstream identity source |
| DORA | Research programme and its software delivery metrics |
| DXI | Developer Experience Index, the effectiveness measure in DX Core 4 |
| Exit (escape hatch) | Documented way for a team to leave the golden path while still meeting mandatory controls |
| FinOps | Practice of managing technology spend with shared accountability between engineering and finance |
| FOCUS | FinOps Open Cost and Usage Specification: a common schema for billing data |
| GitOps | Operating model where the desired state is declared in Git and reconciled automatically |
| Golden path | The supported, opinionated way to build and run a kind of software. Also "paved road" |
| Hub Leader | Matrix lead for one stack who drives adoption and governance without direct reports |
| IDP | Internal Developer Platform: the whole system. The Internal Developer **Portal** is only its front door |
| MCP | Model Context Protocol. A standard for connecting AI agents to tools and data |
| MONK | Platform metrics shorthand: Market share, Onboarding time, NPS, Key customer metrics |
| OpenCost | CNCF project for Kubernetes cost allocation |
| PaaS | Platform as a Service, for example Heroku or Cloud Foundry |
| Platform as a product | Running the platform with users, a backlog, feedback loops and adoption metrics |
| QBR | Quarterly Business Review with a vendor |
| Scorecard | Automated checklist that grades a service against standards |
| Score | Open workload specification (CNCF sandbox): one file that describes what a service needs |
| Showback / chargeback | Showing teams their cost / billing them for it |
| SLA / SLO | Service level agreement (contractual) / service level objective (internal target) |
| SOW | Statement of Work with a supplier |
| SPACE | Productivity framework: Satisfaction, Performance, Activity, Communication, Efficiency |
| TCO | Total cost of ownership, including people |
| TechDocs | Backstage's docs-as-code feature |
| Thinnest viable platform | The smallest set of capabilities that removes real friction |
| Toil | Repetitive manual operational work that scales with load |
| Twelve-factor | Set of principles for applications that run well on a platform |
